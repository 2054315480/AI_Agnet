# 智能客服 Agent — 系统架构文档

## 一、项目概述

本项目是一个基于 Spring AI + Vue 3 的智能客服系统，面向中国移动等大型企业的客服场景。系统集成了意图识别、槽位填充、多轮对话管理、知识库检索（FAQ 精确匹配 + BM25/PgVector 混合检索）、指代消解、拒识转人工等核心能力，并提供批量测试、对话分析仪表盘、对话日志导出等运营工具。

- **后端**：Spring Boot 3.5.10 + Java 21 + Spring AI 1.1.2
- **前端**：Vue 3 + Vite 5 + Vue Router 4
- **LLM**：阿里云 DashScope（OpenAI 兼容模式），模型 qwen-plus
- **向量库**：PgVector (PostgreSQL 扩展)，1024 维，COSINE_DISTANCE + HNSW 索引
- **稀疏检索**：BM25 (Apache Lucene)
- **数据库**：PostgreSQL 15+

## 三、核心数据流

### 3.1 客服对话流程（SSE 流式）

```
用户输入
  │
  ├── [1] CustomerServiceAgent.step()
  │   │
  │   ├── [2] DialogStateManager — 多轮上下文恢复
  │   │   ├── 检查槽位填充状态 (SLOT_FILLING / CLARIFYING)
  │   │   ├── 指代消解（"它" → 具体实体，规则 + LLM 双通道）
  │   │   └── 话题切换检测
  │   │
  │   ├── [3] IntentClassifier.classify()
  │   │   ├── Tier 1: 关键词预筛（150+ 关键词，12 个意图）
  │   │   │   └── 命中 → 高置信度直接返回，跳过 LLM
  │   │   └── Tier 2: LLM 语义分类（低温，JSON 结构化输出）
  │   │       └── 解析 JSON → IntentResult (intent + slots + confidence)
  │   │
  │   ├── [4] 决策路由
  │   │   ├── REQUEST_HUMAN → 直接转人工 → SSE "handoff"
  │   │   ├── CHITCHAT → 直接回复寒暄 → SSE "answer"
  │   │   ├── 置信度 < 0.5 → 澄清追问 → SSE "clarification"
  │   │   └── 其他意图 → 进入 ReAct 循环 →
  │   │
  │   ├── [5] ToolCallAgent.think()
  │   │   └── 调用 DashScope LLM (qwen-plus) + Tool Definitions
  │   │       ├── 模型决定调用 searchKnowledgeBase → SSE "tool_call"
  │   │       └── 模型返回最终答案 → SSE "answer" → 流程结束
  │   │
  │   ├── [6] ToolCallAgent.act()
  │   │   └── 执行 searchKnowledgeBase → KnowledgeSearchService
  │   │       ├── Tier 1: FAQ 精确匹配 (char bigram Jaccard)
  │   │       │   └── 得分 ≥ 0.6 → 直接返回 + 同类别推荐问题
  │   │       └── Tier 2: BM25 + PgVector RRF 混合检索 (topK=10)
  │   │       └── SSE "tool_result" + "suggested_questions"
  │   │
  │   └── [7] 再次 think() — 基于工具结果生成最终答案
  │       ├── 引用知识库内容 + 标注来源 [来源：文档名] [条目编号：kbId]
  │       ├── 知识库无匹配 → 告知用户 + 建议转人工
  │       └── SSE "answer" → SSE "done"
  │
  └── [8] onComplete → 持久化对话数据 + upsert 分析指标
```

## 四、组件详细说明

### 4.1 CustomerServiceAgent

继承自 ToolCallAgent → ReActAgent → BaseAgent，是整个对话的核心编排器。

| 属性/方法 | 说明 |
|-----------|------|
| `intentClassifier` | 意图识别 + 槽位提取（规则 + LLM 双通道） |
| `dialogStateManager` | 多轮对话状态管理（Redis/内存） |
| `step()` | 每轮对话入口，包括意图识别 → think → act 全流程 |
| `initSession(sessionId)` | 初始化会话，加载 System Prompt 模板 |
| `resolveReferences()` | 指代消解（规则 + LLM 补全） |
| `injectSearchQueryHint()` | 确保 LLM 使用完整原文搜索，防止关键词简化 |
| `sendAnswerAndSaveContext()` | SSE 推送 + 更新 lastBotMessage + 持久化 |

**ReAct 循环参数**：
- `maxStep = 10`
- `MIN_CONFIDENCE = 0.5`
- `HANDOFF_OUT_OF_SCOPE_THRESHOLD = 2` 轮
- `MAX_TURNS_BEFORE_HANDOFF = 15` 轮

### 4.2 IntentClassifier

| 层级 | 机制 | 说明 |
|------|------|------|
| Tier 1 | 关键词预筛 | 150+ 关键词覆盖 12 种意图，命中则高置信度直接返回 |
| Tier 2 | LLM 语义分类 | 构建分类 Prompt → 调用 qwen-plus → 解析 JSON 输出 |

**意图列表（10 种业务意图）**：
ORDER_QUERY, ORDER_CANCEL, ORDER_REFUND, PRODUCT_INFO, PRODUCT_RECOMMEND, COMPLAINT, AFTER_SALE, POLICY_QUERY, REQUEST_HUMAN, CHITCHAT, CLARIFICATION, OUT_OF_SCOPE

### 4.3 KnowledgeSearchService

两级知识检索架构：

| 层级 | 方法 | 算法 | 阈值 |
|------|------|------|------|
| Tier 1 | FAQ 精确匹配 | 字符 bigram Jaccard + 多维相似度融合 | ≥ 0.6 |
| Tier 2 | 混合检索 | BM25 (topK=10) + PgVector Cosine (topK=10) → RRF (k=10) | - |

**RRF 融合公式**：`score(doc) = Σ 1/(k + rank_i)` where k = CANDIDATE_TOP_K = 10

### 4.4 DialogStateManager

| 功能 | 实现 |
|------|------|
| 会话创建/恢复 | 内存 Map (sessionId → DialogState)，可扩展 Redis |
| 状态字段 | currentIntent, filledSlots, pendingSlots, dialogPhase, turnCount, consecutiveOutOfScope, lastBotMessage |
| 状态转换 | GREETING → SLOT_FILLING/CONFIRMING → RETRIEVING → ANSWERING → HANDOFF/CLOSED |
| 安全机制 | 最大轮次 100、状态过期 24h |

### 4.5 ToolCallAgent

继承 ReActAgent，实现标准 ReAct 模式的 think() + act()。

**think() 流程**：
1. 注入 nextStepPrompt → messagesList
2. 构建 allMessages = systemPrompt + messagesList
3. 构建 OpenAiChatOptions（含 tools 定义，禁用自动执行）
4. 调用 chatModel.call()，解析响应
5. 无 tool_calls → SSE "answer" → 返回 false
6. 有 tool_calls → SSE "tool_call" → 返回 true

**act() 流程**：
1. 获取 toolCallchatResponse 中的 tool calls
2. 通过 toolCallingManager.executeToolCalls() 执行
3. 更新 messagesList 为 conversationHistory
4. SSE "tool_result" 推送执行结果

### 4.6 CustomerServiceTools

| 工具名 | 说明 | 模式 |
|--------|------|------|
| `searchKnowledgeBase` | 知识库检索（FAQ + 混合检索） | 真实 |
| `queryOrder` | 订单查询 | 演示 |
| `queryProduct` | 产品查询 | 演示 |
| `cancelOrder` | 取消订单 | 演示 |
| `submitRefund` | 提交退款 | 演示 |
| `transferToHuman` | 转接人工 | 真实 |

## 十、关键算法伪代码

### FAQ 相似度计算

```
function computeFaqSimilarity(query, faqQuestion):
    if query == faqQuestion: return 1.0
    
    score = 0.0
    
    // 1. 去空白精确匹配
    if stripSpaces(query) == stripSpaces(faqQuestion): return 1.0
    
    // 2. 双向包含 + 长度比例
    if faqQuestion.contains(query) or query.contains(faqQuestion):
        score += 0.7 * min(len(query), len(faqQuestion)) / max(len(query), len(faqQuestion))
    
    // 3. 中文分词关键词匹配
    queryWords = segment(query)
    faqWords = segment(faqQuestion)
    matched = count(intersection(queryWords, faqWords))
    score += 0.3 * matched / len(queryWords)
    
    // 4. 编辑距离加分（短文本 + 高相似度）
    if len(query) <= 15 and editSimilarity(query, faqQuestion) > 0.8:
        score += 0.2 * editSimilarity
    
    // 5. 字符差异惩罚
    charJaccard = charBigramJaccard(query, faqQuestion)
    if charJaccard < 0.98:
        score -= 0.1 * (1 - charJaccard)
    
    // 6. 高字符重叠加分
    if charJaccard >= 0.65 and len(query) >= 5:
        score += 0.30
    
    return clamp(score, 0, 1)
```

### RRF 融合

```
function rrfFusion(bm25Results, vectorResults, k=10):
    scores = Map<String, Double>()
    
    for each (doc, rank) in bm25Results:
        scores[doc.id] += 1/(k + rank)
    
    for each (doc, rank) in vectorResults:
        scores[doc.id] += 1/(k + rank)
    
    return sortByScoreDescending(scores).take(topK)
```
